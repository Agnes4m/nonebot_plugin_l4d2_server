## 数据结构

bot所在文件夹下

```txt
举例：
└── data
    └── L4D2
        ├── image                 # 头像缓存
        │   └── players
        │       └── ...
        ├── custom_backgrounds    # 自定义背景图片
        │   ├── bg1.png
        │   ├── bg2.jpg
        │   └── ...
        ├── sb_pages.json         # SourceBans URL 映射 {组名: URL}
        ├── l4d2.json             # 旧版 l4_reload 命令的 URL 映射（兼容保留）
        ├── 关键词1.json          # 每组一个文件，内容 {组名: [服务器列表]}
        ├── 关键词2.json
        └── ...
...
```

新增一个json文件，格式如下,文件名与需要响应的指令一致
`关键词1.json`、`关键词2.json` 都是合法的单组文件。

```json
{
  "呆呆": [
    {
      "id": 1,
      "ip": "43.248.188.17:27031"
    },
    {
      "id": 2,
      "ip": "43.248.188.17:27032"
    }
  ]
}
```

**json文件命名并不影响功能**，只是为了区别不同用户上次json，防止重复覆盖，如果一个json需要多个服组,例如一个json文件中，可以包括`呆呆`和`新呆呆`两个指令

```json
{
    "呆呆": [
        {
            "id": 1,
            "ip": "43.248.188.17:27031"
        },
        {
            "id": 2,
            "ip": "43.248.188.17:27032"
        }
    ],
    "新呆呆":[
        {
            "id": 2,
            "ip:: "43.248.188.17:27032"
        }
    ]
}
```

> 自 1.x.x 版本起，服务器组文件从 `data/L4D2/l4d2/<tag>.json` 扁平化为 `data/L4D2/<tag>.json`。
> 旧版布局会在首次启动时自动迁移：单文件 `l4d2.json` 中的服务器数据会拆分为对应组的 JSON，
> `l4d2/` 子目录中的文件会上移一层；旧文件会保留为 `.bak` 备份。
